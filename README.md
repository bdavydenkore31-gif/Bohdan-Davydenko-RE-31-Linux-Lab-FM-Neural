# Лабораторна робота — нейромережеве розпізнавання FM

**Богдан Давиденко · РЕ-31**  
Середовище: Raspberry Pi OS · Python 3 · FastAPI · NumPy/SciPy · scikit-learn · JavaScript/Canvas

## 1. Мета роботи

Розробити вебзастосунок, який приймає сирі комплексні відліки SDR, розпізнає FM серед інших сигналів і показує результат на водоспаді.

Після обробки сторінка показує **висновок за всім файлом**, водоспад із прокручуванням і таблицю знайдених ділянок. Якщо у файлі одночасно є FM та інші сигнали, це вказується у висновку.

## 2. Послідовність обробки запису

1. **Читаємо I/Q.** Браузер передає вибраний файл серверу. Драйвер отримує компоненти I та Q і параметри запису.
2. **Будуємо водоспад.** FFT з вікном Ганна показує енергію за частотою й часом. Спектральний пошук знаходить центри активних ділянок.
3. **Готуємо входи нейромережі.** Кожну ділянку переносимо до нульової частоти, фільтруємо й перераховуємо до 320 кГц. Із I/Q-вікна отримуємо 480 спектральних та 83 амплітудно-фазові ознаки. Вони описують форму спектра й зміну сигналу за часом.
4. **Розпізнаємо модуляцію.** Навчена MLP із прихованими шарами 128 і 64 нейрони оцінює FM / не FM. Аналіз повторюється кожні 0,5 с; медіана трьох коротких вікон зменшує одиночні помилки.
5. **Формуємо результат.** Сусідні рішення об’єднуються в ділянки. За всіма ділянками запису формується загальний висновок, а браузер малює рамки й таблицю.

Назва файлу та центральна радіочастота потрібні для читання й підписів шкали. Аудіодемодуляція для розпізнавання не використовується.

### Використані технології

| Технологія | Призначення |
| --- | --- |
| NumPy та SciPy | Комплексні I/Q, FFT, фільтрація, ресемплінг і виконання збережених ваг |
| scikit-learn | Навчання MLP через Adam, нормалізація входів і калібрування оцінок |
| FastAPI та Uvicorn | Приймання файлів, фоновий аналіз і передавання результату |
| JavaScript та Canvas | Завантаження запису, водоспад, прокрутка й таблиця |

## 4. Запуск

Потрібен Python 3.10 або новіший. Команди виконуються з кореня проєкту.

**Raspberry Pi OS, 64 біти:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Відкрий `http://127.0.0.1:8010`, вибери I/Q-файл і натисни **«Аналізувати»**. Повторне навчання для запуску не потрібне.

Підтримуються двоканальні PCM WAV, 8/16/32 біти, частота відліків 320 кГц — 5 МГц, тривалість до 10 хвилин і розмір до 4 ГБ. Центр зчитується з назви `baseband_...Hz...`, метаданих WAV SDR# або вводиться вручну.

Для сирого I/Q без заголовка вкажи частоту відліків і формат: u8, i16 LE або float32 LE. Для наданого `baseband_96400000Hz_09-17-43_23-11-2026.wav` використано **u8, I потім Q, 2,048 МГц** — параметри попереднього записування. У самому сирому файлі ці параметри не збережені.

## 5. Навчання моделі

Набір `ai/datasets/labeled_iq.npz` містить 2568 реальних комплексних вікон по 8192 відліки. Джерела й підстави розмітки збережено в сусідньому JSON:

- **FM:** канал попередньої лабораторної на 96 МГц та канали нового запису на 96 і 96,4 МГц.
- **Не FM:** надані ADS-B, airband та міжканальні ділянки нового запису.
- Додаткові негативи утворюються контрольованими AM, CW, QPSK, перемішуванням фаз і шумом.

Перші 70% часу кожного джерела використовуються для навчання, наступні 15% — для валідації, останні 15% — для перевірки. Часові частини розділені проміжками. Спотворені версії одного вікна залишаються в його вибірці. Нормалізація навчається на train; епоха, калібрування й поріг вибираються за validation.

Повторне навчання на включеному наборі:

```bash
python -m ai.train --samples 16000 --epochs 85
```

Підготовка набору заново з трьох наданих повних записів:

```powershell
python -m ai.prepare_captures --samples-dir "/home/pi/sdr_samples"
```

## 6. Результати та їхнє читання

- **«У файлі є FM»** — знайдено хоча б одну впевнено розпізнану FM-ділянку. Наявність інших сигналів зазначається окремо.
- **«FM не виявлено»** — знайдені ділянки розпізнано як не FM.
- **«Недостатньо даних для висновку»** — впевнених рішень немає.

Час із Зелені рамки на водоспаді позначають FM, жовті — не FM. Позначка не FM об’єднує інші модуляції та шум. Фільтр **«Лише FM»** змінює рамки й таблицю; загальний висновок залишається за всім файлом.

Водоспад прокручується колесом або смугою праворуч. Масштаб **«Видимий час»**, повзунок і натискання на час у таблиці переносять до потрібної ділянки.

На відкладених реальних вікнах знайдено **104 із 106 FM**, хибних FM — **0 серед 266 негативів**. У повних ADS-B та airband записах FM не позначено. Докладні вимірювання збережено в `ai/models/training.json` та `evaluation.json`.

Ці результати стосуються наданих записів. На слабких або незнайомих сигналах можливі пропуски й помилки; зокрема, вони залишаються на частині синтетичного QPSK.
